# Payment Service Implementation Plan

**Goal:** Implement every requirement in the copied specification autonomously.
**Architecture:** Quarkus 3, Java 21, explicit JDBC in one JTA transaction, PostgreSQL unique payment identity and ordered account locks. Transport parsing is separate from immutable domain commands. JWT authentication is mandatory.
**Spec:** payment-processing-requirements.md

1. Add failing parser tests covering JSON/XML equivalence, duplicate/unknown fields, XXE and aggregate validation; implement hardened parser and immutable command.
2. Add PostgreSQL migration with immutable financial history and balance baseline; implement transaction service, durable rejections, bounded lock/retry handling and reconciliation.
3. Add authenticated HTTP resources, media negotiation, correlation, rate limits, metrics and errors.
4. Add integration tests covering balances, ledger, authorization, replay/conflict, concurrency, rollback and durable retrieval. Run mvn verify against PostgreSQL.
5. Deliver OpenAPI, Docker Compose, CI, load test and operations instructions. Document evidence and performance limitations honestly.

User instructions explicitly authorize all design decisions and waive approval gates. Work stays inside folder 05. No financial data deletion flow is provided.

Completed: strict shared parsing, transaction service and persistence, HTTP/JWT/limits/observability, Flyway/database immutability, reconciliation, OpenAPI and operating documentation.
