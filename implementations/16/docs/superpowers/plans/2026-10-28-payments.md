# Payment Backend Implementation Plan

> Execute inline as authorized by the task. Technical decisions and approvals are delegated to the implementer.

**Goal:** Deliver the complete synchronous JOD payment backend.
**Architecture:** Strict transport, immutable domain command, explicit JDBC transactional service, scoped OAuth API.
**Tech Stack:** Java 21, Spring Boot, PostgreSQL, Flyway, JUnit, Testcontainers.
**Spec:** payment-processing-requirements.md and ../specs/2026-10-28-payment-design.md

## Global Constraints
Decimal amounts have exact 3-place scale. No negative balances. Atomic debit/credit/ledger. Unique payment ID. No user approval prompts. Work only inside directory 16.

## Review Focus
Duplicate keys/elements, amount coercion, untrusted source identity, concurrent duplicate requests, uncertain commit outcomes.

## Tasks
- [x] Write parser/validation tests; verify failure before adding strict shared parsing and immutable commands.
- [x] Write PostgreSQL transaction tests; verify failure before implementing migrations, deterministic row locks, idempotency, immutable outcomes and rollback.
- [x] Write HTTP/security tests; implement JWT/scopes, content negotiation, consistent errors, request limits and correlation.
- [x] Verify concurrency, reconciliation, rejection replay, restart durability and injection rollback.
- [x] Add OpenAPI, Compose, container, CI, load test, operational docs; run mvn verify and report evidence and limitations.
