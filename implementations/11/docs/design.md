# Design and implementation plan
Autonomous decisions authorized by AGENTS.md. Use Java 21 and Spring Boot with explicit PostgreSQL JDBC transactions instead of ORM to make financial locking visible. Single service with API, immutable domain, application, persistence, security and observability layers. Parse bounded JSON with strict duplicate/type detection; parse XML with hardened StAX into the same transport fields. Canonical command hashes length-prefixed business fields. PostgreSQL unique UUID registration serializes concurrent duplicate requests; deterministic account locks protect balance invariants. Store definitive business refusals, roll back infrastructure errors, retry bounded transient transaction errors with unchanged ID. JWT scopes plus owner/delegate checks protect financial operations. Persist original receipt and rejection; return only after TransactionTemplate commits. Database triggers enforce ledger/payment immutability, paired balanced entries and account baseline reconciliation. Tests cover strict formats, actual PostgreSQL transactions, races and injected failures. Docker Compose, CI, OpenAPI, operational runbook and load scenario complete delivery. Implementation order: parser tests; parser/domain; schema and service with database acceptance tests; HTTP/security/telemetry; docs and full Maven verification.
